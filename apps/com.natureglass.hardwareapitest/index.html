Hardware API Test

Phase A verification for the Brewser device chooser. Each button calls a hardware Web API's requestDevice() — a picker should appear listing matching devices; pick one (or press B to cancel) and the result shows below.

Environment

WebUSB — navigator.usb

"Request device" calls requestDevice({ filters: [{}] }) (matches every attached USB device), so the chooser lists everything on the USB-C port. Plug a device in first.

—

Web Bluetooth — navigator.bluetooth

The Switch BLE scanner is filter-based: enter a service UUID your device advertises — a 16-bit alias like 0x180D or a full 128-bit UUID. Then "Request device" scans (~8 s) and shows the chooser.

—

WebSerial — navigator.serial

Requests a CDC-ACM serial port, opens it, and runs a read loop. Type + Write sends bytes; received bytes append below. (ESP32 native-USB / Arduino / Pico-class devices; FTDI/CP210x/CH340 not yet supported.)

—

WebHID — navigator.hid

Requests an HID device, opens it, parses its report descriptor, and logs incoming input reports. Send an output report with a report ID + hex bytes.

—

Web MIDI — navigator.requestMIDIAccess

Requests MIDI access (a one-shot permission prompt, not a device picker), lists USB-MIDI ports, logs incoming messages, and sends a test note to the first output.

—

Web NFC — NDEFReader

scan() shows a permission prompt, then waits for a tag tap. Citron has no reader, so use "Simulate tag" to inject a fake NDEF reading and verify parsing. write() needs real hardware + a tag.

—

Simulation (Citron / no hardware)

Citron doesn't emulate USB-host or BLE, so the real buttons above find nothing. These call the engine's __nxjsDeviceChooserProbe to open the real chooser (with the real permission gate) using fake devices — so you can verify the picker UI, title, selection, cancel (B) and gate without hardware.
